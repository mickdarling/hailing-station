# Reply masking report (#1213)

Part of #1213. This reports masking only: no change to the zeroing predicate,
reply routing, voice processing, the setting, tap-to-talk, or the 400 ms tail.
#1225's proposed live microphone behavior remains separate work.

Legacy playback-busy `echo_guard on=…` records keep their shape. Effective
`echo_guard` records carry `masking`, `reason`, `capture`, and `count=1`; off edges
include monotonic elapsed `ms`, bounded to the diagnostics integer range.
Reasons are `setting`, `reply_not_routed`, `plain_capture`, and `tap_to_talk`.
For overlapping reasons, precedence is tap-to-talk, setting, then
plain capture or an unrouted reply. A reason change emits off then on **at the
same instant**, a zero-length unmasked gap. Consumers must not interpret that
pair as an open microphone.

Capture modes are `plain`, `vpio`, and `other` for a generic capture of unknown
mode. A `capture_state` snapshot records the mode at stream start, including an
unmasked VPIO stream. Edges are observed at capture-buffer boundaries using the
same locked predicate that decides whether to zero samples. Off is observed on
the first unmasked buffer after a tail, or capture end if earlier. Timings have
buffer-cadence resolution; they are not audio hardware timestamps.

The host advertises `device_diagnostics_reply_masking` with its diagnostics sink.
`sendDiagnostics` removes entire new reports, including new keys and tokens,
for hosts without it; an all-filtered batch sends nothing. Old hosts receive the
legacy shape, and new hosts accept old devices. The schema is generated by
`hail-protocol-gen`. Existing host-side diagnostic session attribution remains;
no audio, text, reply/request IDs, or stream IDs are added.

Round 2 replaces capture-path event construction with a preallocated 500-slot
ring. It stores scalar reason/capture enums, on/off, monotonic instant, interval
start for off durations, and enable generation. Appending, resetting, and
oldest-first overflow are constant-time and allocate no transition storage.
Round 3 starts one long-lived main-actor drainer per capture, with an
`AsyncStream<Void>` wake created at begin using `.bufferingNewest(1)`. The
capture path appends scalars under the lock and yields the existing continuation
only on empty-to-nonempty; it creates no task. The main actor
copies the scalars into an already allocated destination under the lock, then
converts instants to timestamps and constructs events outside it. Overflow uses
`events_dropped code=app_buffer`; diagnostics' separate rate/capacity limits
still apply. Lost records can leave incomplete intervals.

Enable generations and logger identity discard stale prepared data. The first
buffer after re-enabling or attaching a different log snapshots fresh mode and
masking state. Reattaching the same log preserves its interval. Pending masking
records flush before legacy playback and tap edges. Stale capture buffers and
completion callbacks cannot report for a replacement stream. Each drainer's
callback checks its capture token before flushing. Capture end, stop, and
replacement finish the old wake and cancel its task; end also synchronously
flushes the last transitions. The owner stops its task on deinitialization,
and the drainer uses a weak guard reference. Synchronous playback/tap flushes
remain available.

A doctor/status current-stream summary and accumulated masked time remain a
follow-up beyond the four-production-file budget. Physical proof requires an
owner-approved **device app build**: the **Mac app with plain capture** (the main
case), or **iOS**, followed by a live captured-output check. Package builds and
synthetic tests prove neither physical behavior nor a live round trip. This
work does not include app builds, installs, uploads, or TestFlight delivery.
