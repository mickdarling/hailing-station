# Station build footer

Part of #131. The main Station screen displays `Version … · Build …` in a persistent bottom safe-area footer on both compact and regular layouts. It reads only `CFBundleShortVersionString` and `CFBundleVersion` from the running app bundle; no endpoint, account, signing, or device identifiers are included. Missing metadata is explicitly shown as `Unavailable`.

The footer is independent of connection and destination state. It uses a Dynamic Type caption that can wrap, stays outside the Station's scrolling content, and exposes one text element with accessibility identifier `station.build-info`. VoiceOver and UI automation can read both identifiers from that element's label.

`StationBuildInfoTests` covers exact release identifiers, a supplied bundle's metadata, and missing/invalid values. `StationBuildFooterTests` covers a fresh unconfigured Station, a configured offline Mac, scrolling, rotation, and the largest accessibility text category in a simulator. Every footer check compares the entire label with the generated UI-test bundle's metadata; app and UI-test targets share the version/build settings in `project.yml`. The app and test bundle's generated plists were also checked for an exact match. These checks do not prove live selected-target behavior, physical VoiceOver behavior, or a TestFlight update.

An initial extra destination-browser probe passed on the iPhone simulator but failed on the iPad simulator: after tapping `station.destination`, the expected browser navigation bar did not appear. Footer visibility assertions passed before that tap. This reproduces the separate #102 picker/automation finding; the final footer suite does not depend on destination-browser presentation or claim that issue is fixed.
