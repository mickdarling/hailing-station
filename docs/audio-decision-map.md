# Audio decision map

Epic #1483 covers the path from a microphone to an addressed request and from a reply back to the listener. A lit microphone, an open ambient stream, a recognized speaker, a dispatched request and audible playback are five different observations.

This map follows Hailing Station `415382086a0c53156785e8306486b30eec495e2f` and RightyO `f13478021bf387e9fcfdcf7ddc7a65ec61402422`. It describes what the source does under the conditions in each row. The failure modes are symptoms from the epic brief. Each proposed connection between a symptom and a cause is marked (inferred). Physical audibility and the settings of an installed system require separate evidence.

Each numbered row covers one decision or related branches at the same boundary. References are repository-relative `file:line`. Paths beginning with `src/rightyo/` refer to the RightyO checkout. The native Mac and mobile targets share `Apps/Hail-iOS/`.

[Mac capture](#1-mac-capture) · [iOS capture](#2-ios-and-ipados-capture) · [haild lifecycle](#3-haild-ambient-lifecycle) · [RightyO stages](#4-rightyo-stages) · [Playback and echo](#5-playback-and-echo) · [Multi-device](#6-multi-device) · [Failure modes](#failure-modes) · [Gaps](#gaps)

**Where to look.** In the Mac and iOS capture tables, unqualified event names refer to optional **device diagnostics**. This includes `ambient_start`, `ambient_stop`, `host_refusal`, `capture_state`, `capture_error`, `route_change`, `interruption_begin`, `interruption_end`, `app_background`, `app_foreground`, `reply_playback_start`, `reply_playback_end`, `reply_playback_error`, `echo_guard` and `events_dropped` wherever they appear. When the device sends a batch and haild admits it, the host diagnostics sink stores records in `diagnostics.jsonl` (`Sources/HailDaemonKit/Diagnostics/DiagnosticLog.swift:8`, `Sources/HailDaemonKit/Diagnostics/DiagnosticLog.swift:25`). Device event names and field spellings come from `Sources/HailProtocol/Control.swift:920`. Supplementary route and mask details depend on negotiated support (`Sources/HailCore/Diagnostics/DeviceDiagnostics.swift:501`, `Sources/HailCore/Diagnostics/DeviceDiagnostics.swift:567`). Unqualified host events in the haild, playback and multi-device tables go to **haild JSON** on daemon stderr (`Sources/haild/main.swift:349`). These records have an `event` name and may carry `sessionID`, `endpoint` and `detail` (`Sources/HailDaemonKit/Listener/WebSocketListener.swift:2110`). Names shown inside `detail` are fields in that string. Square brackets mark optional fields and slashes separate alternative values. H20’s hold and resolution notices go to the Apple unified log under `held-requests` (`Sources/HailDaemonKit/Listener/HeldRequests.swift:130`). In the RightyO table, `session`, `transcript`, `attention`, `conversation`, `request`, `request_outcome`, `override`, `dismiss`, `privacy` and `owner_voice` are **child stdout** events consumed by haild. Station wire controls travel over the WebSocket. Internal notifications, sink calls, in-memory counters, status files and CLI output are identified separately. **stderr** means a child-side diagnostic. The parent drains stderr and counts bytes, so these lines are generally unavailable in the haild log (`Sources/HailDaemonKit/Input/RightyoChildSupport.swift:128`, `Sources/HailDaemonKit/Input/RightyoChildProcess.swift:64`). The field lists omit speech, payload contents, identifiers and route-name values. *none* means no dedicated event at that branch. *invisible* means no dedicated owner-facing app indication. Quoted UI strings are literals or templates with angle brackets standing for dynamic values.

## GAPS

These are proposals, grouped by the decisions they would explain. New event names and quoted UI strings below are **proposals**. Where a proposal spans processes, the device would record its decisions in device diagnostics, the child would report decisions to haild, and the host would record its decisions in haild JSON. Fields represent enums, booleans, counts, durations or per-process sequence numbers. Private speech needs no per-turn trace.

- **Privacy switch origin and proof (D01–D05, D08, D12, H14, R22, R24).** Add `privacy_transition origin=tap/reconnect_reassert/recovery/voice/live_holder/park/overflow/snapshot requested effective_before effective_after proof result`. Set origin where the action begins. Record snapshot reads only for peers advertising `mode_snapshot`, and identify repeated proofs separately from new armings. Show “Privacy restored after reconnect” or “Privacy is still on. Listening is available again” for the corresponding outcomes.
- **Host time, startup and retention (H01–H02, H08–H10, H12–H18, H21).** Add UTC `timestamp`, process-local `sequence` and monotonic `uptime_ms` to haild lifecycle events. Emit `listener_start_failed stage=options/policy/bind reason=<enum>` for failures preceding listener readiness. Once a stream requests a child, emit `ambient_child_start_failed stage=spawn/config/start reason=<enum>` for startup failures and `ambient_child_exit started terminal_seen protocol_result exit_kind exit_code` when the child exits, including after a protocol failure. A finite config error code from the child would distinguish schema from missing assets without retaining stderr. Show “Host listener could not start” for a listener failure or “Listening stopped because the speech configuration was rejected” for a confirmed child configuration failure.
- **Restart boundaries (H18, D03–D04, D09–D12).** Emit `ambient_state_initialized retention=memory_only prior_privacy_state=unknown prior_streams_restored=0` on fresh process start. Show “Host restarted. Confirm privacy before resuming listening.” Specify which privacy intent, if any, should survive a restart, who owns it and how it is reproved before opening capture. The current process has no previous holder count to report.
- **Capture permission, device choice and ownership (M01–M06, M10–M13, I01–I10, I14–I20).** Add `capture_decision stage=permission/selection/activation/engine/tap/rebuild/stop reason outcome platform mode input_kind output_kind` at ownership changes/refusals; report stale-input fallback and VPIO/plain selection reason. When the window already has a Talk owner, show “Talk is already using the microphone in this window”. Report cleanup in progress separately. For routing, expose “Headset output · built-in microphone” using observed kinds.
- **Capture loss, background and reconnect (M07–M09, I07–I13, D07, D11–D12).** Emit bounded `capture_loss stage=tap/convert/encode/send reason count duration_ms` and `capture_recovery cause attempt outcome`. Include keepalive render/session-restore outcomes and whether capture, interruption or an active, unpaused, unsuppressed reply held release, including while muted. Proposed Status text “Microphone restarted after audio stopped arriving” distinguishes successful repair from a user stop.
- **Host admission, backpressure and child replacement (H03–H11, H15–H17).** Add `ambient_admission stage=target/format/rate/ingress/stdin/reload reason outcome` and interval counts of discarded segments, withheld private bytes and inserted silence. Show “Host stopped listening: audio input closed” or “Host stopped listening: no audio arrived” from the matching terminal reason. Emit a sanitized config revision/validation result per spawn to link identical failures over retries.
- **Hearing and attribution (R02–R12, R23, R25).** For public audio, aggregate `speech_windows opened below_gate finalized empty_valid recovered lost` and `turn_attribution outcome=unlabelled/ambiguous/overlap/tentative/bound reason`. Surface “Heard speech; speaker unconfirmed” where an eligible unsent turn already appears. Aggregate existing public `attention.decision` standing fields and isolated unlabelled comparison outcomes (R09, R16) at the host boundary. Keep diagnostic scores separate from binding decisions. The privacy path needs only control/proof outcomes.
- **Attention and dispatch (R13–R21, R23, R26, H19–H20, H22).** Emit one public `attention_outcome result=sent/held/not_sent reason mode engagement cue binding recipient_kind bar_profile` for the final decision, including unengaged abstention, guest policy, presence, meeting and host refusal. Show “Heard · not sent: outside a conversation” or “Meeting mode: owner address not verified” only when that gate decided the result. Record clip eligibility and the host transport result separately in `ack_outcome eligible host_send_result`. A proposed `device_received` field would require a new Station receipt (P07).
- **Reply routing, loss and feedback (P01–P17).** Add `playout_decision stage=route/admit/buffer/start/hold/end/mask/ack/yield reason outcome` on edges and counts for no recipient, stale/duplicate data, budget, silence/echo suppression, underrun and lost final. For yield, relate the existing local notice, counters and histogram (P13) to the later host verdict. Use route/engine kinds and interval counts. Show “Reply audio held while the mic is in use”, “Reply had no active output” or “Acknowledgement unavailable” on the matching path. A software end event cannot measure physical audibility.
- **Other devices and modes (D02–D13, R14–R15).** Add `mode_resolution kind origin=live/park/overflow/snapshot/automatic/explicit stale_verdict device_match effective recording` when those values change. Show “Privacy is held by another connection”, “Meeting mode resumed without recording” or “Other voices detected · name required” when supported by the decision. Show only a device class for handoff. The claim match serves liveness and recording decisions, not identity proof.
