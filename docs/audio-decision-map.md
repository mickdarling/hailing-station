## GAPS

The owner has set the restart and health requirements in #1483. The event names and UI strings suggested below are **proposals**. Where a proposal spans processes, the device would record its decisions in device diagnostics, the child would report decisions to haild, and the host would record its decisions in haild JSON. Fields represent enums, booleans, counts, durations or per-process sequence numbers. Private speech needs no per-turn trace.

- **Privacy switch origin and proof.** Add `privacy_transition origin=tap/reconnect_reassert/recovery/voice/live_holder/park/overflow/snapshot requested effective_before effective_after proof result`. Set origin where the action begins so a future owner tap can be distinguished from an app reconnect reassertion without asking the owner. Record snapshot reads only for peers advertising `mode_snapshot`, and identify repeated proofs separately from new armings. Show “Privacy restored after reconnect” or “Privacy is still on. Listening is available again” for the corresponding outcomes.
- **Host time, startup and retention.** Add UTC `timestamp`, process-local `sequence` and monotonic `uptime_ms` to haild lifecycle events. Emit `listener_start_failed stage=options/policy/bind reason=<enum>` for failures preceding listener readiness. Once a stream requests a child, emit `ambient_child_start_failed stage=spawn/config/start reason=<enum>` for startup failures and `ambient_child_exit started terminal_seen protocol_result exit_kind exit_code` when the child exits, including after a protocol failure. A finite config error code from the child would distinguish schema from missing assets without retaining stderr. Show “Host listener could not start” for a listener failure or “Listening stopped because the speech configuration was rejected” for a confirmed child configuration failure.
- **Restart boundaries.** The owner decided that restarts must preserve the last explicit privacy choice (On or Off) and must never restore an inherited stale hold. If Ambient was on, resume automatically on the same device when possible and show the reason if resumption fails. Implementation is pending. A proposed `ambient_state_initialized` event would report whether the explicit choice was restored, failed to restore or could not be verified. On fresh host startup, report the prior in-memory holder count as unknown. Show “Host restarted. Confirm privacy before resuming listening” only if the privacy restore failed or could not be verified. [Owner decision](https://github.com/mickdarling/hailing-station/issues/1483#issuecomment-7223019076)
- **Capture permission, device choice and ownership.** Add `capture_decision stage=permission/selection/activation/engine/tap/rebuild/stop reason outcome platform mode input_kind output_kind` at ownership changes and refusals. Report stale-input fallback and VPIO/plain selection reason. When the window already has a Talk owner, show “Talk is already using the microphone in this window”. Report cleanup in progress separately. For routing, expose “Headset output · built-in microphone” using observed kinds.
- **Capture loss, background and reconnect.** Emit bounded `capture_loss stage=tap/convert/encode/send reason count duration_ms` and `capture_recovery cause attempt outcome`. Include keepalive render/session-restore outcomes and whether capture, interruption or an active, unpaused, unsuppressed reply held release, including while muted. Proposed Status text “Microphone restarted after audio stopped arriving” distinguishes successful repair from a user stop.
- **Host admission, backpressure and child replacement.** Add `ambient_admission stage=target/format/rate/ingress/stdin/reload reason outcome` and interval counts of discarded segments, withheld private bytes and inserted silence. Show “Host stopped listening: audio input closed” or “Host stopped listening: no audio arrived” from the matching terminal reason. Emit a sanitized config revision/validation result per spawn to link identical failures over retries.
- **Hearing and attribution.** For public audio, aggregate `speech_windows opened below_gate finalized empty_valid recovered lost` and `turn_attribution outcome=unlabelled/ambiguous/overlap/tentative/bound reason`. Surface “Heard speech · speaker unconfirmed” where an eligible unsent turn already appears. Aggregate existing public `attention.decision` standing fields and isolated unlabelled comparison outcomes (R09, R16) at the host boundary. Keep diagnostic scores separate from binding decisions. Limit privacy reporting to control and proof outcomes.
- **Attention and dispatch.** Emit one public `attention_outcome result=sent/held/not_sent reason mode engagement cue binding recipient_kind bar_profile` for the final decision, including unengaged abstention, guest policy, presence, meeting and host refusal. Show “Heard · not sent: outside a conversation” or “Meeting mode: owner address not verified” only when that gate decided the result. Record clip eligibility and the host transport result separately in `ack_outcome eligible host_send_result`. A proposed `device_received` field would require a new Station receipt.
- **Reply routing, loss and feedback.** Add `playout_decision stage=route/admit/buffer/start/hold/end/mask/ack/yield reason outcome` on edges and counts for no recipient, stale/duplicate data, budget, silence/echo suppression, underrun and lost final. For yield, relate the local notice, counters and histogram to the later host verdict. Use route/engine kinds and interval counts. Show “Reply audio held while the mic is in use”, “Reply had no active output” or “Acknowledgement unavailable” on the matching path. Keep physical audibility as a separate observation.
- **Other devices and modes.** Add `mode_resolution kind origin=live/park/overflow/snapshot/automatic/explicit stale_verdict device_match effective recording` when those values change. Show “Privacy is held by another connection”, “Meeting mode resumed without recording” or “Other voices detected · name required” when supported by the decision. Show only a device class for handoff. Use the claim match for liveness and recording decisions.
