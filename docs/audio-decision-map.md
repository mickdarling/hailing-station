# Audio decision map

Epic #1483 covers the path from a microphone to an addressed request and from a reply back to the listener. A lit microphone, an open ambient stream, a recognized speaker, a dispatched request and audible playback are five different observations.

This map follows Hailing Station `46813b35bdd3b96cbbfa38739eb8f047aa0b255d` and RightyO `f13478021bf387e9fcfdcf7ddc7a65ec61402422`. It describes what the source does under the conditions in each row. The failure modes are symptoms from the epic brief. Their possible causes are **inferred**. Physical audibility and the settings of an installed system require separate evidence.

Each numbered row covers one decision or related branches at the same boundary. References are repository-relative `file:line`. Paths beginning with `src/rightyo/` refer to the RightyO checkout. The native Mac and mobile targets share `Apps/Hail-iOS/`.

**Evidence conventions.** Device event names and field spellings come from `Sources/HailProtocol/Control.swift:920`. Device diagnostic recording is optional. Supplementary route and mask details depend on negotiated support (`Sources/HailCore/Diagnostics/DeviceDiagnostics.swift:501`, `Sources/HailCore/Diagnostics/DeviceDiagnostics.swift:567`). Daemon JSON records have an `event` name and may carry `sessionID` and `detail` (`Sources/HailDaemonKit/Listener/WebSocketListener.swift:2110`). Names shown inside `detail` are fields in that string. H20’s hold and resolution notices go to the Apple unified log under `held-requests` (`Sources/HailDaemonKit/Listener/HeldRequests.swift:130`). RightyO **wire** means child stdout, consumed by haild. **stderr** means a child-side diagnostic. The parent drains stderr and counts bytes, so these lines are generally unavailable in the haild log (`Sources/HailDaemonKit/Input/RightyoChildSupport.swift:128`, `Sources/HailDaemonKit/Input/RightyoChildProcess.swift:64`). Field names are shown without speech, payloads, device identifiers or route names. *none* means no dedicated event at that branch. *invisible* means no dedicated owner-facing app indication. Quoted UI strings are literals or templates with angle brackets standing for dynamic values.

## GAPS

These are proposals, grouped by the decisions they would explain. Event names and quoted strings below are **proposed**, not current output. Fields represent enums, booleans, counts, durations or per-process sequence numbers. Private speech needs no per-turn trace.

- **Privacy switch origin and proof (D01–D05, D08, D12, H14, R22, R24).** Add `privacy_transition origin=tap/reconnect_reassert/recovery/voice/live_holder/park/overflow/snapshot requested effective_before effective_after proof result`. Set origin where the action begins. Record snapshot reads only for peers advertising `mode_snapshot`, and identify repeated proofs separately from new armings. Show “Privacy restored after reconnect” or “Privacy is still on. Listening is available again” for the corresponding outcomes.
- **Host time, startup and retention (H01–H02, H08–H10, H12–H18, H21).** Add UTC `timestamp`, process-local `sequence` and monotonic `uptime_ms` to haild lifecycle events. Emit `listener_start_failed stage=options/policy/bind reason=<enum>` for failures preceding listener readiness. Once a stream requests a child, emit `ambient_child_start_failed stage=spawn/config/start reason=<enum>` for startup failures and `ambient_child_exit started terminal_seen protocol_result exit_kind exit_code` when the child exits, including after a protocol failure. A finite config error code from the child would distinguish schema from missing assets without retaining stderr. Show “Host listener could not start” for a listener failure or “Listening stopped because the speech configuration was rejected” for a confirmed child configuration failure.
- **Restart boundaries (H18, D03–D04, D09–D12).** Emit `ambient_state_initialized retention=memory_only privacy_state=unknown prior_streams_restored=0` on fresh process start. Show “Host restarted. Confirm privacy before resuming listening.” Specify which privacy intent, if any, should survive a restart, who owns it and how it is reproved before opening capture. The current process has no previous holder count to report.
- **Capture permission, device choice and ownership (M01–M06, M10–M13, I01–I10, I14–I20).** Add `capture_decision stage=permission/selection/activation/engine/tap/rebuild/stop reason outcome platform mode input_kind output_kind` at ownership changes/refusals; report stale-input fallback and VPIO/plain selection reason. When the window already has a Talk owner, show “Talk is already using the microphone in this window”. Report cleanup in progress separately. For routing, expose “Headset output · built-in microphone” using observed kinds.
- **Capture loss, background and reconnect (M07–M09, I07–I13, D07, D11–D12).** Emit bounded `capture_loss stage=tap/convert/encode/send reason count duration_ms` and `capture_recovery cause attempt outcome`. Include keepalive render/session-restore outcomes and whether capture, interruption or audible playback held release. Proposed Status text “Microphone restarted after audio stopped arriving” distinguishes successful repair from a user stop.
- **Host admission, backpressure and child replacement (H03–H11, H15–H17).** Add `ambient_admission stage=target/format/rate/ingress/stdin/reload reason outcome` and interval counts of discarded segments, withheld private bytes and inserted silence. Emit a sanitized config revision/validation result per spawn to link identical failures over retries.
